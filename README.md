# tank-software-design

Запуск: `./gradlew run` (в IDE: Gradle → application → run).

Сборка и тесты: `./gradlew build`.

Нужен JDK 11. На Apple Silicon для исходной версии libGDX нужен JDK x64 и Rosetta 2.

Управление: стрелки или WASD. Переход на соседнюю клетку занимает 0,4 секунды.
Деревья блокируют движение; танк поворачивается даже при заблокированном пути.

- `model` — состояние и правила игры без графики.
- `input` — обработка клавиш и регистрация действий.
- `command` — команды, которые вызываются с клавиатуры или AI.
- `control` — стратегии управления и их совместный запуск.
- `graphics` — отображения объектов, карта и ресурсы.
- `level` — модель уровня и стратегии его загрузки.
- `GameLoop` — последовательность ввода, обновления модели и отрисовки через интерфейсы.
- `TankGame` — адаптер жизненного цикла libGDX.
- `DefaultGameFactory` — сборка исходной сцены и её настройки.
- `GameDesktopLauncher` — запуск окна.

Танк принимает `Passability`, длительность движения и начальное направление.
Поле хранит `Obstacle`: новый тип препятствия реализует `occupies`, менять `Field` не нужно.
`GameModel` обновляет любые `Updatable`; объекты передаются в конструктор или добавляются через `addObject`.

`TankControls` принимает `KeyBindings`, действие движения и карту клавиш.
Порядок записей в карте определяет приоритет направлений.
`KeyboardHandler.bindHeld(command, keys)` выполняет команду при удержании клавиши,
`bindPressed(command, keys)` — один раз при нажатии. Когда появится стрельба,
её можно зарегистрировать отдельно: `keyboard.bindPressed(tank::shoot, SPACE)`.

Отображения зависят от `Positioned` и `MovementState`, а не от конкретных моделей.
Текстуры, интерполяция и угол неподвижных объектов передаются при создании отображений.
`GameRenderer` принимает фон через `Renderer` и список `SpriteRenderer`;
для нового отображения достаточно добавить реализацию в список при сборке сцены.
Цвет фона, фоновые тайлы, текстуры и клавиши задаются в `DefaultGameFactory`.
Другую сцену можно подключить через фабрику, переданную в `TankGame`.

Тесты модели, ввода и игрового цикла запускаются без окна и OpenGL.
Они проверяют движение и столкновения, новые правила проходимости и препятствия,
другие привязки клавиш, добавление обновляемых объектов и замену компонентов игрового цикла.

Наполнение уровня задаётся стратегией `LevelLoader`, которую принимает `DefaultGameFactory`.
`FileLevelLoader` читает текстовый файл, `RandomLevelLoader` генерирует деревья и позицию игрока.
Обе стратегии возвращают `Level`, который хранит размеры, деревья, начальную клетку и проверяет проходимость.

По умолчанию игра читает `src/main/resources/levels/default.txt`, упакованный в ресурсы приложения.
Другой файл: `./gradlew run --args='--level levels/mine.txt'`.
Случайный уровень: `./gradlew run --args='--random'`.
Для повторяемой генерации можно задать seed: `./gradlew run --args='--random 42'`.
В IDE эти же аргументы передаются задаче Gradle → application → run.

Формат файла:

```text
__T_T_____
_TT__TTTT_
________T_
TTTT__T__T
____X_____
__________
```

`T` — дерево, `X` — начальная клетка игрока, `_` — пустая клетка.
Строки одинаковой длины, `X` ровно один; пробелы и другие символы не допускаются.
Первая строка отображается сверху. Поддерживаются LF и CRLF, завершающий перевод строки необязателен.
Размеры поля берутся из файла; фон повторяет исходные тайлы, камера показывает всё поле.
Танк не может выйти за границы уровня.

Случайный режим создаёт поле 10×8 с 16 деревьями. Размеры, число деревьев и источник случайности
передаются в конструктор `RandomLevelLoader`. Деревья занимают разные клетки и не пересекаются
с начальной позицией игрока. Новая стратегия подключается через `LevelLoader` без изменения фабрики игры.

На любой карте дополнительно появляются до пяти AI-танков в случайных свободных клетках.
Если клеток не хватает, их число уменьшается. Позиция игрока берётся из уровня;
его танк синий, танки AI имеют тёмный оттенок. Генерация танков и их управление случайны
при каждом запуске, в том числе при фиксированном seed генератора уровня.

`MoveCommand` хранит направление и действие движения. `KeyboardHandler` и
`RandomControlStrategy` реализуют `ControlStrategy` и выполняют команды через `Command`.
AI выбирает случайную команду, когда танк неподвижен; если путь заблокирован,
на следующем кадре он пробует снова. `CompositeControlStrategy` обновляет все стратегии
перед обновлением модели. Новые команды можно привязывать к клавишам или передавать AI
без изменения этих обработчиков.

`TankField` создаёт танки с общей проверкой проходимости и учитывает их как `Obstacle`.
Движущийся танк занимает исходную и целевую клетки; исходная освобождается только после
завершения движения. Поэтому танки не могут поменяться местами встречным движением
или одновременно начать переход в одну клетку. Деревья и границы блокируют всех одинаково.
`RandomTankSpawner` получает размеры области, максимальное число танков, длительность
движения и `Random`; он выбирает разные свободные клетки без повторных попыток.

Тесты дополнительно проверяют случайное размещение, команды и обе стратегии управления,
резервирование клеток, встречное движение и совместную работу игрока с AI.
Длительная симуляция на файловой и случайной картах проверяет отсутствие пересечений
и выходов за границы без графического окружения.
